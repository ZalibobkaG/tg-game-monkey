# 🐒 Обезьянка — Telegram-игра

Офлайн-пати-игра. Компания сидит в одной комнате, у каждого телефон.
Бот раздаёт секретные карточки и даёт синхронный сигнал — всё остальное происходит вживую.

---

## 1. Правила

**Роли**
- **Мирные** (N−1) — получают карточку с 10 пронумерованными действиями. Список **одинаковый у всех** — это основа игры.
- **Обезьянка** (1, при 12+ игроках — 2) — во всех 10 пунктах написано «🐒 ТЫ ОБЕЗЬЯНКА».

**Ход игры**
1. Админ создаёт комнату, выбирает колоду и число раундов
2. Все получают карточку в ЛС (скрыто, по кнопке)
3. Раунд: админ жмёт «Погнали» → всем отсчёт 3-2-1 → в один момент приходит **№7**
4. Все резко делают действие №7. Обезьянка копирует соседей и молится
5. Так N раундов (по умолчанию 5)
6. Голосование: все в ЛС выбирают, кто обезьянка. **Ждём всех без таймаута**
7. При равенстве голосов — **переголосование** между лидерами
8. Раскрытие, очки, итог

**Очки (за одну игру, между играми не копятся)**
| Событие | Очки |
|---|---|
| Обезьянку не нашли | Обезьянке **+3** |
| Обезьянку нашли | Каждому проголосовавшему верно **+1** |
| Обвинили невиновного | Обезьянке **+1** за каждый ошибочный голос |

**Параметры**
- Игроков: **4–15** (при 12+ — **две обезьянки**, они не знают друг о друге)
- Раундов: 3 / 5 / 7, по умолчанию 5
- В карточке 10 действий, выбираются случайно из колоды (50–60 штук), без повторов внутри игры

**Важные нюансы правил**
- **Обезьянка голосует обязательно** — иначе её вычислят по факту неголосования
- **Обезьянка не видит номер действия** — только «🐒 КОПИРУЙ!». Тогда в живом обсуждении вопрос «какое было действие?» становится ловушкой
- Номера действий внутри игры не повторяются

## 2. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Рантайм | **Node.js 20 + TypeScript** | выбор заказчика, путь к Mini App позже |
| Бот | **grammY** | лёгкий, типизированный, хорошие плагины |
| БД | **PostgreSQL + drizzle-orm** | миграции, jsonb для снапшотов |
| Состояние игры | **in-memory Map + write-through снапшот** | один инстанс, Redis не нужен |
| QR | `qrcode` (png в память) | вход по скану с экрана админа |
| Деплой | Docker Compose на VPS, long polling → webhook | |

**Обязательные плагины grammY:**
- `@grammyjs/auto-retry` — ловит 429 и повторяет
- `@grammyjs/transformer-throttler` — очередь под лимиты (30 msg/s глобально, 1 msg/s в чат)

Без них синхронная рассылка на 12+ игроков ляжет на первом лимите.

## 3. Синхронный сигнал

Telegram не доставит 12 сообщений в одну миллисекунду. Решение — **отсчёт + предзагрузка**:

```
T-3.0  sendMessage всем: «⏳ Приготовьтесь…»   → запоминаем message_id
T-3.0  editMessageText: «3️⃣»
T-2.0  editMessageText: «2️⃣»
T-1.0  editMessageText: «1️⃣»
T-0.0  Promise.all(editMessageText) → «№7» / «🐒 КОПИРУЙ!»
```

Сообщение уже лежит в чате — правка приходит мгновенно, а общий отсчёт делает разброс в ±300 мс незаметным.
Перед игрой бот просит всех включить звук.

## 4. Защита от подглядывания

Все сидят рядом — экран соседа виден. Поэтому карточка приходит **скрытой**:

```
🎴 Твоя карточка готова
[ 👀 Показать (5 сек) ]
```

Нажал → текст раскрылся → через 5 секунд `editMessageText` возвращает заглушку.
Смотреть можно сколько угодно раз, но экран не остаётся открытым.

## 5. Вход в комнату — два потока

**A. ЛС + QR (основной)**
Админ создаёт комнату в ЛС → бот присылает код `ABC123` и QR с `t.me/bot?start=room_ABC123` → все сканируют прямо с его экрана.

**B. Групповой чат**
Бот добавлен в чат компании → `/game` → сообщение с кнопкой «Войти» и живым списком игроков. Карточки всё равно уходят в ЛС.

**Проверка ЛС перед стартом:** если игрок зашёл через группу, но не запускал бота — `sendMessage` вернёт 403.
В лобби у каждого игрока флаг `dm_ok`; зелёная галочка появляется только после успешного пинга в ЛС. Старт заблокирован, пока кто-то не готов.

## 6. Модель данных

```
users        (id, tg_id, username, first_name, created_at)
decks        (id, slug, title, description, is_premium, price_rub, sort)
deck_items   (id, deck_id, text)
user_decks   (user_id, deck_id, acquired_at, payment_id)      -- права на колоду
rooms        (id, code, admin_user_id, chat_id?, state, deck_id, rounds_count, created_at)
room_members (room_id, user_id, seat, is_active, dm_ok, joined_at)
games        (id, room_id, deck_id, actions_snapshot jsonb, monkey_user_ids, state, started_at, ended_at)
rounds       (id, game_id, idx, action_index, started_at)
votes        (game_id, voter_id, target_id, created_at)
payments     (id, user_id, provider, external_id, deck_id, amount, currency, status, created_at)
```

`actions_snapshot` — jsonb с 10 текстами, зафиксированными на старте игры. Правка колоды не должна ломать историю.

**FSM комнаты:** `lobby → dealing → round_wait → round_signal → voting → results → lobby`
Снапшот в Postgres после каждого перехода — переживаем рестарт сервера.

## 8. Монетизация: премиум-колоды

- **Базовая колода** — бесплатно навсегда, ~30 действий
- **Тематические колоды** — 100 ₽ за штуку, 50–60 действий:
  - `hot` **18+** — раскованное, для своих
  - `hardcore` **Хардкор** — сложные и похожие между собой действия, обезьянке почти нереально
  - `icebreaker` **Для незнакомых компаний** — безопасные жесты, знакомство через игру
- Покупает **админ**, играет вся комната — правильно, снижает трение

⚠️ **Правовой момент.** Telegram требует продавать цифровые товары только за **Stars (XTR)**. Фиат через ЮKassa — для физических товаров/услуг, и в РФ это юрлицо/самозанятость + чеки по 54-ФЗ. Поэтому «100 ₽» на релизе станет эквивалентом в звёздах.

**Сейчас:** `StubProvider` — кнопка «Купить» сразу выдаёт право и пишет запись в `payments`. Позже подменяется на `StarsProvider` без переписывания выдачи прав.

**Продуктовый риск:** это контентный бизнес. Если платных колод не будет — платить не за что. Минимум 4 качественные колоды к запуску.

## 10. Риски

| Риск | Решение |
|---|---|
| Игрок не запускал бота → нет ЛС | Флаг `dm_ok`, блокировка старта |
| Игрок вышел / заблокировал бота посреди игры | Помечаем `is_active=false`; если ушла обезьянка — игра аннулируется |
| Админ ушёл | Передача прав следующему по `seat` |
| Рестарт сервера в середине раунда | Снапшот FSM, восстановление комнат на старте |
| Подглядывание в чужой экран | Скрытая карточка с автоскрытием |
| Колода приелась | Колоды = и монетизация, и retention |
| Дубли платежей, двойной тап | Идемпотентность по `external_id`, локи на комнату |
| 152-ФЗ | Храним только `tg_id` и username |

## 11. Принятые решения

| Вопрос | Решение |
|---|---|
| Название бота | **Обезьянка** (юзернейм подобрать в @BotFather) |
| Платные колоды | 18+ · Хардкор · Для незнакомых компаний |
| Таймаут голосования | нет, ждём всех |
| Равенство голосов | переголосование между лидерами |
| Две обезьянки при 12+ | да |
| Хостинг | VPS (Docker Compose) |

**Правило переголосования:** при равенстве лидеров запускается второй тур только между ними.
Если и второй тур ничей — обезьянка считается не найденной и побеждает.
Локально Docker нет — dev-база ставится через Homebrew, compose нужен только на VPS.
